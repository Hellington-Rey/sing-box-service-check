# История изменений

## 1.10.1 — 20 августа 2026

### Добавлено

- Вкладка VPN автоматически определяет WireGuard или AWG Tools и поддерживает AWG 1.5, 2.0 и 3.0 из стандартного конфига. Адреса без маски автоматически получают `/32` или `/128`; компоненты `kmod`, tools и netifd-протокол проверяются до записи UCI.
- При неудачной установке VPN в LuCI показываются конкретные недостающие пакеты, состояние команды и полный вывод `opkg`/`apk`.
- При обновлении из терминала установщик предлагает добавить отсутствующий `bind-dig` или восстановить несовместимые `bind-libs`/`bind-dig`; интерактивный вопрос работает и при запуске через `wget | sh`.
- В LuCI список недостающих зависимостей показывается до подтверждения, а выбранная установка пакетов выполняется тем же проверенным релизным установщиком.

## 1.9.1 — 16 августа 2026

### Добавлено

- Отдельная вкладка «Тест DNS» с фоновым замером времени ответа публичных резолверов по UDP, DoH и DoT.
- Консольные команды `dns` и `dns-start`, валидация домена, прогресс и настоящая отмена фонового DNS-теста.

### Исправлено

- Ошибка `dig` больше не заменяется общей фразой про защищённый DNS: рядом с кратким описанием показывается диагностическая строка от самого `dig`, в том числе для UDP.
- Перед тестом проверяется фактический запуск `dig -v`: несовместимость `bind-dig` и `bind-libs` теперь останавливает тест до 61 одинаковой ошибки и показывает команду восстановления пакетов.
- Время DNS-запроса запрашивается у `dig` в микросекундах: ответы быстрее миллисекунды больше не отображаются как `0 мс`, а отсутствие метрики не маскируется нулём.
- Результаты в каждой группе UDP, DoH и DoT автоматически сортируются от самого быстрого успешного ответа к медленному; ошибки располагаются после ответивших серверов.

## 1.9.0 — 13 августа 2026

### Добавлено

- Настоящая отмена фоновой проверки с завершением только принадлежащего заданию процесса и очисткой временного network namespace.
- Ожидаемый маршрут `any`, `proxy` или `direct` для каждой цели и отдельные вердикты при несовпадении либо невозможности подтвердить маршрут.
- История десяти последних запусков в `/var/run` с наглядным сравнением статуса, outbound и времени ответа.
- Безопасный отчёт для поддержки: копирование текста и скачивание JSON без секретов, адресов клиента и разрешённых IP.
- Импорт и экспорт пользовательских профилей JSON с проверкой на backend до сохранения.
- Диагностика backend, версии, Clash API, DNS-конфигурации и FakeIP, а также отдельная проверка цепочки DNS.
- Команды `doctor` и `repair` для проверки установки и восстановления файлов текущей версии из локальной копии.
- Транзакционное обновление с резервной копией, автоматическим откатом и детерминированным recovery-архивом.
- Автоматическая сборка opkg-feed и GitHub Release с контрольными суммами.

### Изменено

- Версия проекта хранится в одном файле `VERSION` и проверяется сборкой и CI.
- Backend и LuCI разделены на поддерживаемые исходные модули в `src/`; deploy-файлы собираются детерминированно.
- CI собирает официальный runtime ucode и выполняет матрицу сценариев Tachyon, Forkop, Podkop, override, битого Clash API и валидации профилей.
- Ответ Clash API считается доступным только при корректном JSON, а не только по коду завершения команды.

### Исправлено

- Устранена ошибка загрузки LuCI `ReferenceError: UI_VERSION is not defined` после перехода на версию из backend capabilities.

## 1.8.0 — 12 августа 2026

### Добавлено

- Поддержка Tachyon как отдельного диагностического backend.
- Автоматическое определение `/usr/bin/tachyon` с приоритетом перед оставшимися после миграции Forkop/Podkop.
- Чтение пути конфигурации Sing-box и клиентского интерфейса из `tachyon.settings`.
- Проверка состояния через `tachyon get_status` и определение outbound через `tachyon clash_api get_connections`.
- Отображение Tachyon и его состояния в LuCI.
- Регрессионные проверки Tachyon в установщике и пакетах.

### Безопасность и совместимость

- Специфичные исправления Forkop скрыты и заблокированы на Tachyon, даже если старый бинарник Forkop остался после миграции.
- Поддержка Forkop и оригинального Podkop, имя пакета, команды и пользовательские настройки сохранены.
- Оба самодостаточных установщика, IPK, opkg-feed и APK-сборщик пересобраны для версии 1.8.0.

## 1.7.0 — 12 августа 2026

### Изменено

- Публичное название проекта и интерфейса изменено на **Sing-box Service Check**.
- Основная команда теперь `sing-box-service-check`.
- Основной самодостаточный установщик теперь называется `install-sing-box-service-check.sh`.
- Название страницы в LuCI и метаданные пакета приведены к новому бренду.

### Совместимость

- Имя пакета `luci-app-forkop-servicecheck` сохранено, поэтому обновление не создаёт второй пакет.
- Команда `forkop-servicecheck`, старый установщик и каталоги настроек сохранены для существующих установок.
- Старый адрес GitHub обслуживается совместимым репозиторием-мостом, чтобы встроенное обновление версии 1.6.0 не потеряло доверенный источник.

## 1.6.0 — 12 августа 2026

### Добавлено

- Блок «Обновление модуля» в LuCI с проверкой последнего стабильного GitHub Release.
- Кнопка фоновой установки новой версии с отображением этапов и результата.
- Консольные команды `update-check`, `update-start` и `update-status`.
- Проверка официального URL asset, GitHub digest, локального SHA-256 и версии внутри установщика перед запуском.
- Восстановление опроса состояния после кратковременного перезапуска `rpcd`.

## 1.5.0 — 12 августа 2026

### Добавлено

- Поддержка оригинального Podkop без изменения имени пакета `luci-app-forkop-servicecheck`.
- Автоматическое определение установленного backend: Forkop или Podkop.
- Чтение пути конфигурации Sing-box и LAN-интерфейса из настроек Podkop.
- Проверка состояния Podkop и определение outbound через штатный Clash API Sing-box.
- Отображение найденного backend и его состояния в LuCI.

### Изменено

- Вкладка «Фикс Forkop» теперь показывается только при установленном Forkop.
- Запуск специфичных исправлений дополнительно блокируется backend, если Forkop отсутствует.
- Убрана жёсткая зависимость IPK от пакета `forkop`, чтобы модуль устанавливался поверх Podkop.
- Проверка Netflix переведена с требующего авторизации API/CDN на публичную статическую цель `assets.nflxext.com`.
- Обновлены README, описание пакета и установщик.

### Совместимость

- Имя пакета, команда `forkop-servicecheck` и пользовательские настройки сохранены.
- Если Forkop и Podkop установлены одновременно, автоматически выбирается Forkop.
